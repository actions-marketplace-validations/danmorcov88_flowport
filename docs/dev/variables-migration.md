# Variables to parameter contexts: what was verified on NiFi 1.28.1

Date: 2026-09-16. The fixture `tests/fixtures/nifi-1.28.1/flow.json.gz` was
migrated with `flowport migrate variables` and the result placed as
`conf/flow.json.gz` in an unmodified `apache/nifi:1.28.1` container, next to
a second container running the original flow. The checks live in
`tests/integration/test_migrate_variables_nifi1.py` and run in CI on every
push to `main`.

## Sources

| Fact | Source |
|---|---|
| Expression Language looks up a FlowFile attribute before a process group variable, then the registry file, JVM properties and environment variables; the first match wins. | [EL guide, "Expression Language Hierarchy"](https://nifi.apache.org/docs/nifi-docs/html/expression-language-guide.html#expression-language-hierarchy) |
| Parameter names allow letters, digits, `-`, `_`, `.` and space. | [User guide, parameter name restriction](https://nifi.apache.org/docs/nifi-docs/html/user-guide.html#name-parameter-restriction) |
| A sensitive property can only reference a sensitive parameter and vice versa. | [User guide, sensitive parameters](https://nifi.apache.org/docs/nifi-docs/html/user-guide.html#using-parameters-with-sensitive-properties) |
| A process group does not inherit its parent's parameter context. | [User guide, assigning a context](https://nifi.apache.org/docs/nifi-docs/html/user-guide.html#assigning_parameter_context_to_PG) |
| Parameter contexts can inherit from other contexts (`inheritedParameterContexts`), since 1.15.0. | [NIFI-8490](https://issues.apache.org/jira/browse/NIFI-8490) |
| Which parameter wins when a context and an inherited context define the same name is not documented in the user guide. | [NIFI-9891](https://issues.apache.org/jira/browse/NIFI-9891) (open); verified below |
| At startup the flow synchronizer resolves inherited contexts by name. | [NIFI-10096](https://issues.apache.org/jira/browse/NIFI-10096) |

## Observations

| Situation | Result on 1.28.1 |
|---|---|
| `parameterContexts` entry generated by flowport (`identifier` derived like NiFi does, `UUID.nameUUIDFromBytes(instanceIdentifier)`; `instanceIdentifier` a UUIDv5 of the source group id; `description` on the context and on each parameter) | Loaded without warnings: `VersionedFlowSynchronizer Added Parameter Context Variables Variables`. The context keeps the generated ids. |
| `parameterContextName` set on a process group that had none | The group is bound to the context (`GET /flow/process-groups/{id}` shows `parameterContext.component.name`). |
| Created contexts listed after the contexts they inherit from | No `cannot find a Parameter Context` warning (compare NIFI-10096). |
| Context `Child Variables` defines `shared` and inherits `Variables Variables`, which also defines `shared` | `GET /parameter-contexts/{id}?includeInheritedParameters=true` reports `shared` from `Child Variables` (value `from-child`) and `host`, `port` from `Variables Variables`. **The context's own parameter wins over an inherited one**, which matches how a child group's variable shadowed its parent's. The 1.x API does not return an `inherited` flag; the origin is in `parameter.parameterContext`. |
| `${path}` rewritten to `#{path}` on GetFile "Input Directory" | Valid, and validated for real: with `${path}` NiFi's directory validator returns "Expression Language Present" and skips the check; with `#{path}` the parameter is substituted first and the literal `/data/in` is checked. A migrated processor can therefore turn invalid on 1.x when the configured value was wrong all along. The integration test creates the directories so that both instances validate the same way. |
| Group `Existing Context` (context `Fixture Context` with parameter `host`, variable `host`) | Left unchanged by flowport; NiFi keeps both. Reported as `NIFI2-VARIABLE-PARAMETER-COLLISION`. |
| Every other processor and controller service | Same validation errors as in the original flow (the fixture has unconnected relationships and ghosted components on purpose). |

## How to reproduce

```
pytest -m integration            # needs Docker; about one minute with the image pulled
```

Or by hand: `docker create` with `NIFI_WEB_HTTP_PORT`, `NIFI_WEB_HTTP_HOST=0.0.0.0`
and `NIFI_SENSITIVE_PROPS_KEY`, copy `flow.json.gz` into `conf/` from a tar
whose entry is owned by uid 1000 (`docker cp` alone writes it as root and NiFi
refuses to start), `docker start`, then poll `GET /nifi-api/flow/process-groups/root`.
Use the same host and container port: NiFi 1.x rejects requests whose `Host`
header does not match its own port.
